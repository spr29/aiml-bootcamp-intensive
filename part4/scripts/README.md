# Utility Scripts

Utility scripts for managing data and infrastructure.

## Available Scripts

### `list_kb_versions.py`
Lists all knowledge base versions in S3.

**Usage:**
```bash
python scripts/list_kb_versions.py
```

**Features:**
- Shows all timestamped versions
- Displays document counts
- Shows creation timestamps
- Highlights latest version
- Provides S3 URIs for Bedrock configuration

**Example Output:**
```
Found 3 version(s):

Version 1: v_20260117_103042
  S3 Location: s3://ecom-rag-bucket/knowledge-base/v_20260117_103042/
  Documents: 93
  Created: 2026-01-17T10:30:42

Version 2: v_20260117_143521
  S3 Location: s3://ecom-rag-bucket/knowledge-base/v_20260117_143521/
  Documents: 94
  Created: 2026-01-17T14:35:21

LATEST VERSION: v_20260117_143521
```

---

### `upload_to_s3.py`
Original S3 upload script with interactive bucket name input.

**Usage:**
```bash
python scripts/upload_to_s3.py <bucket-name>
```

**Features:**
- Uploads knowledge base chunks to S3
- Creates organized folder structure (policies/, faqs/)
- Generates manifest file
- Provides Bedrock Knowledge Base setup instructions

**Example:**
```bash
python scripts/upload_to_s3.py ecom-rag-bucket
```

---

### `1.5_upload_kb_to_s3.py`
S3 upload script with automatic versioning.

**Usage:**
```bash
python scripts/1.5_upload_kb_to_s3.py
```

**Features:**
- **Automatic versioning** with timestamps (e.g., `v_20260117_103042`)
- Lists existing versions before upload
- Creates new version folder - never overwrites existing data
- Uploads all chunks from `data/knowledge_base_chunks.json`
- Creates individual .txt files for each chunk
- Organizes into policies/ and faqs/ folders
- Generates metadata manifest

**Output Structure:**
```
s3://ecom-rag-bucket/knowledge-base/
  ├── v_20260117_103042/    <- Version 1
  │   ├── policies/
  │   ├── faqs/
  │   └── manifest.json
  └── v_20260117_143521/    <- Version 2 (latest)
      ├── policies/
      │   ├── return_policy_0.txt
      │   ├── return_policy_1.txt
      │   └── ...
      ├── faqs/
      │   ├── faq_0.txt
      │   ├── faq_1.txt
      │   └── ...
      └── manifest.json
```

**Benefits:**
- Version control for knowledge base data
- Safe rollback to previous versions
- Compare performance across versions
- No accidental overwrites
- Audit trail of changes

## Workflow

### Initial Setup

1. **Generate Chunks** (Run Notebook 01)
   ```bash
   # Opens Jupyter
   jupyter notebook notebooks/01_data_exploration_chunking.ipynb
   ```
   This creates `data/knowledge_base_chunks.json`

2. **Upload to S3**
   ```bash
   python scripts/upload_kb_to_s3.py
   ```

3. **Create Knowledge Base**
   - Go to AWS Bedrock Console
   - Create Knowledge Base
   - Point to `s3://ecom-rag-bucket/knowledge-base/`
   - Configure Titan embeddings
   - Wait for ingestion to complete

4. **Update Configuration**
   - Add `KNOWLEDGE_BASE_ID` to `.env`
   - Test with `tests/test_bedrock_kb.py`

### Updating Data

When you modify policy documents or add FAQs:

1. **Regenerate Chunks**
   - Update source data in Notebook 01
   - Re-run chunking cells
   - Save updated `knowledge_base_chunks.json`

2. **Re-upload to S3**
   ```bash
   python scripts/upload_kb_to_s3.py
   ```

3. **Trigger Ingestion**
   - Use Notebook 02
   - Or AWS Console: Sync data source
   - Or API: `start_ingestion_job()`

## Prerequisites

### Environment Variables
```bash
AWS_ACCESS_KEY_ID=your_key
AWS_SECRET_ACCESS_KEY=your_secret
AWS_DEFAULT_REGION=us-east-1
```

### S3 Bucket
- Bucket must exist before running scripts
- Requires PutObject permissions
- Recommended: Same region as Bedrock KB

### Data Files
- `data/knowledge_base_chunks.json` must exist
- Generated by Notebook 01

## Troubleshooting

### Bucket Not Found
```
Error: Cannot access bucket
```
**Solution:** Create bucket first or check bucket name

### Permission Denied
```
Error: Access Denied
```
**Solution:** Verify AWS credentials and IAM permissions

### No Chunks File
```
Error: FileNotFoundError: data/knowledge_base_chunks.json
```
**Solution:** Run Notebook 01 first to generate chunks

### Upload Fails
```
Error: Could not upload filename.txt
```
**Solution:** Check network connectivity and S3 permissions

## Advanced Usage

### Upload to Different Bucket
Edit `upload_kb_to_s3.py`:
```python
BUCKET_NAME = "your-custom-bucket"
```

### Change S3 Prefix
Edit the `KB_PREFIX` variable:
```python
KB_PREFIX = "custom-folder/"
```

### Upload Specific Files Only
Modify the script to filter chunks:
```python
# Only upload FAQ chunks
faq_chunks = [c for c in chunks if c['source'] == 'faq']
```

## Integration with CI/CD

### GitHub Actions Example
```yaml
name: Deploy Knowledge Base

on:
  push:
    paths:
      - 'data/knowledge_base_chunks.json'

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Upload to S3
        env:
          AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
        run: python scripts/upload_kb_to_s3.py
```

This automatically uploads chunks when the file changes.
